## Назначение и зависимости

`chessboardui` — будущая Android-библиотека для отрисовки шахматной доски, взаимодействия с фигурами и анимации переходов.

Согласованные зависимости:

- Kotlin;
- Android;
- Compose;
- `chesscore`.

Библиотека предназначена только для Android. Существующие `android.graphics.Paint` и `nativeCanvas` можно сохранить. Отдельный адаптер между библиотекой и Compose не требуется: composable-функции, Compose-состояние, жесты и выполнение анимаций могут находиться внутри библиотеки.

Используем собственные типы `chesscore`, прежде всего `Piece` и `Square`. Реализация шахматных правил остаётся за границей библиотеки доски.

В выделяемом коде не должно быть зависимостей от:

- chesslib и `chesscorechesslib`;
- `LineController` и моделей `boardmodel`;
- экранов, сценариев тренировки и навигации;
- темы, ресурсов и тестовых тегов приложения;
- Room, сущностей, сервисов и сохранения данных приложения.

Преобразования моделей приложения в данные библиотеки находятся со стороны приложения. Настройки внешнего вида, которые сейчас берутся из темы приложения, потребуется передавать через согласованный контракт.

## Согласованный контракт отображения

Renderer получает снимок расстановки и визуальное состояние доски.

- Расстановка описывается фигурами `Piece` на клетках `Square` из `chesscore`.
- Ориентация определяет сторону, с которой показана доска; она имеет отдельный смысл от стороны очередного хода.
- Приложение передаёт расстановку, ориентацию и внешние оформления клеток.
- Библиотека управляет состоянием выбора и перетаскивания.
- Отрисовка должна поддерживать произвольную расстановку, включая пустую доску, редактор и предпросмотр.
- Для простого отображения не требуется создавать `Position` или проверять шахматную легальность расстановки.

`Position` можно использовать там, где нужны шахматные операции. Его текущий контракт содержит `getFen`, `getSideToMove`, `getPiece`, `getLegalMoves` и изменяющий позицию `applyMove`. Наличие этих методов не нарушает границу библиотеки.

Снимок нужен, чтобы независимо хранить расстановку для отображения. Например, логическая позиция уже содержит два выполненных хода, пока очередь анимаций ещё показывает первый. Текущий изменяемый `Position` сам по себе не хранит предыдущие расстановки и промежуточные координаты фигур.

Отдельные типы `BoardSnapshot` и `BoardPiecePlacement` не вводятся. Развиваем существующие понятия `BoardRenderPiece` и `BoardRenderScene`. Их прежние версии в `ui/boardrender` пока остаются входами старой отрисовки и анимаций; при следующем шаге приложение получит адаптацию к новым типам. `BoardPosition` остаётся моделью приложения.

### Реализованные модели первого шага

| Тип | Поля |
|---|---|
| `BoardRenderPiece` | `piece: Piece`, `square: Square` из `chesscore` |
| `BoardOrientation` | `WHITE`, `BLACK`; ориентация просмотра имеет отдельный смысл от стороны хода |
| `BoardRenderAnimatedPiece` | `fromSquare: Square`, `centerOffset: Offset` |
| `BoardSquareDecoration` | `square: Square`, `fillColor: Color`, `border: BoardSquareBorder? = null` |
| `BoardSquareBorder` | `color: Color`, `widthFraction: Float`; объявлен в `BoardSquareDecoration.kt` |

`BoardRenderScene` содержит ровно шесть полей:

| Поле | Тип и значение по умолчанию |
|---|---|
| `pieces` | Обязательный `List<BoardRenderPiece>`; пустой список допустим |
| `orientation` | Обязательный `BoardOrientation` |
| `decorations` | `List<BoardSquareDecoration> = emptyList()` |
| `dragFromSquare` | `Square? = null` |
| `dragOffset` | `Offset = Offset.Zero` |
| `animatedPieces` | `List<BoardRenderAnimatedPiece> = emptyList()` |

Сцена — обычный класс с доступными только для чтения свойствами. Три входных списка копируются; собственные копии обёрнуты в `Collections.unmodifiableList`. Изменения исходных списков не меняют сцену, порядок элементов сохраняется.

При создании сцены выбрасывается `IllegalArgumentException`, если:

- две фигуры занимают одну клетку;
- `dragFromSquare` или `animatedPieces.fromSquare` указывает на клетку без фигуры;
- источник анимации повторён либо та же фигура одновременно указана для анимации и перетаскивания;
- координаты `dragOffset` или центра анимируемой фигуры содержат `NaN` или бесконечность.

Ошибки клеток указывают проблемную клетку. Оформления могут повторяться на одной клетке и относиться к пустым клеткам. Разные фигуры могут двигаться одновременно. Проверка конечности `dragOffset` выполняется и при `dragFromSquare = null`; конечные координаты за доской допустимы.

### Реализованный стиль

`BoardRenderStyle` содержит семь обязательных полей типа Compose `Color`:

- `lightSquareColor`, `darkSquareColor`;
- `whitePieceColor`, `blackPieceColor`;
- `whitePieceOutlineColor`, `blackPieceOutlineColor`;
- `coordinateColor`, включая прозрачность цвета.

Стиль передаётся renderer отдельно от сцены. Цвета внешних оформлений находятся в `BoardSquareDecoration`. Размеры подписей, пропорции глифов и существующий способ рисования фигур сохранены при реализации функций рисования.

### Реализованная геометрия

В `geometry/BoardGeometry.kt` находятся три публичные функции:

| Функция | Аргументы | Результат |
|---|---|---|
| `calculateSquareTopLeftOffset` | `Square`, `BoardOrientation`, `squareSizePx: Float` | Верхний левый угол клетки: `Offset` |
| `calculateSquareCenterOffset` | `Square`, `BoardOrientation`, `squareSizePx: Float` | Центр клетки: `Offset` |
| `getSquareFromOffset` | `Offset`, `BoardOrientation`, `squareSizePx: Float` | `Square?`; `null` за пределами доски |

Координаты и размер клетки заданы в пикселях. Начало — верхний левый угол доски, X направлен вправо, Y — вниз. Для `WHITE` сверху слева `a8`, для `BLACK` — `h1`.

- Размер клетки должен быть положительным и конечным; иначе все три функции выбрасывают `IllegalArgumentException`.
- Координаты касания должны быть конечными; иначе `getSquareFromOffset` выбрасывает `IllegalArgumentException`.
- Левая и верхняя границы входят в доску, правая и нижняя исключены.
- Любая отрицательная координата даёт `null`, включая значения между `-1` и `0`.
- Внутренняя граница относится к клетке справа или снизу.
- Деление для определения строки и столбца выполняется через `Double`, чтобы не округлять точку перед границей в следующую клетку.

## Реализованное рисование клеток

В `render/BoardSquaresRenderer.kt` находится обычная внутренняя функция `drawBoardSquares(drawScope, squareSizePx, lightSquareColor, darkSquareColor)`. Контекст `DrawScope` передаётся явным параметром.

- Рисует сетку 8×8 от текущего начала координат рисования.
- Размер клетки задаёт её ширину и высоту в пикселях; размер доски — восемь размеров клетки по каждой стороне, независимо от размера `DrawScope`.
- Светлый и тёмный цвета передаются вызывающим кодом.
- Верхняя левая клетка светлая; цвета чередуются по строкам и столбцам.
- Ориентация не требуется: и `a8`, и `h1` светлые.
- Неположительный или неконечный размер клетки приводит к `IllegalArgumentException` до начала рисования.

Функция вызывается из публичной `drawBoardScene` и компонентных Android-тестов.

## Реализованное рисование оформлений клеток

В `render/BoardSquareDecorationsRenderer.kt` находится обычная внутренняя функция `drawSquareDecorations(drawScope, decorations, orientation, squareSizePx)`. Контекст `DrawScope` передаётся явным параметром.

- Положение клеток вычисляется существующей геометрией с учётом ориентации.
- Оформления рисуются по порядку списка, включая повторные оформления одной клетки.
- Для каждого оформления сначала рисуется заливка, затем необязательная рамка.
- `Color.Transparent` сохраняет фон под заливкой; рамка при этом может быть нарисована отдельно.
- Толщина рамки в пикселях равна `squareSizePx * widthFraction`.
- Рамка центрирована по границе клетки: половина толщины находится внутри клетки, половина снаружи. Обрезка по клетке не вводится; это сохраняет расположение `Stroke` в существующей отрисовке приложения.
- Пустой список не изменяет изображение, но размер клетки всё равно проверяется: неположительный или неконечный размер приводит к `IllegalArgumentException` до рисования.

Функция не зависит от расстановки фигур, темы приложения или смысла оформления. Подключение к приложению пока не выполняется.

## Реализованное рисование одной фигуры

В `render/BoardPieceRenderer.kt` находятся обычные внутренние функции `drawPiece(drawScope, piece, centerOffset, squareSizePx, style)` и `resolvePieceGlyph(pieceType)`.

- `Piece.type` выбирает Unicode-глиф: король U+265A, ферзь U+265B, ладья U+265C, слон U+265D, конь U+265E, пешка U+265F.
- Обе стороны используют одинаковую форму глифа. `Piece.side` выбирает цвет заливки и обводки из четырёх соответствующих полей `BoardRenderStyle`.
- `centerOffset` — центр условного квадрата размещения фигуры, а не границ закрашенных пикселей глифа. Координаты заданы в пикселях от текущего начала рисования.
- Ориентация и клетка не нужны. Функция `drawScenePieces` вычисляет центр обычной фигуры через `calculateSquareCenterOffset`; для анимации и перетаскивания берёт готовые координаты из сцены.
- Сохраняются параметры существующего `ui/PieceVisuals.kt`: размер текста `0.82 * squareSizePx`, базовая линия `centerOffset.y - squareSizePx / 2 + 0.76 * squareSizePx`, горизонтальный масштаб короля `1.25`, ферзя `1.15`, остальных фигур `1`.
- Обводка рисуется четырьмя смещениями на один пиксель влево, вправо, вверх и вниз, затем рисуется основной глиф. Толщина этого оформления не масштабируется вместе с клеткой, как и в прежнем коде.
- Размер клетки должен быть положительным и конечным, обе координаты центра — конечными; иначе `IllegalArgumentException` до рисования. Конечные координаты за доской или целью рисования допустимы, ограничение центра не вводится.
- Рисование использует Android `Paint` и Compose `nativeCanvas`, без зависимостей от темы или моделей приложения.

Существующий `ui/PieceVisuals.kt` и его вызовы остаются прежними. Библиотечная `drawPiece` вызывается из `drawScenePieces` и Android-тестов; подключение к приложению не выполняется.

## Реализованное размещение фигур сцены

В `render/BoardScenePiecesRenderer.kt` находится обычная внутренняя функция `drawScenePieces(drawScope, scene, squareSizePx, style)`.

| Порядок | Фигуры | Координаты центра |
|---|---|---|
| 1 | Неподвижные в порядке `scene.pieces` | `calculateSquareCenterOffset` по клетке, ориентации и размеру |
| 2 | Анимируемые в порядке `scene.animatedPieces` | Готовый `centerOffset` элемента |
| 3 | Перетаскиваемая | Готовый `scene.dragOffset` |

- Движущиеся фигуры исключаются из первого прохода; копии на исходных клетках не рисуются.
- Фигура для анимации и перетаскивания находится в расстановке по исходной клетке. Ссылки и конечность готовых координат уже проверены `BoardRenderScene`.
- Координаты движущихся фигур используются как есть, без повторного применения ориентации и без ограничения центров границами доски.
- Каждая фигура рисуется через `drawPiece` с переданным стилем и размером клетки.
- Размер клетки проверяется до рисования, в том числе для пустой сцены. Неположительный или неконечный размер приводит к `IllegalArgumentException`.
- Пустая сцена сохраняет изображение. Функция не рисует клетки, оформления или подписи и не выполняет анимацию во времени.

Функция вызывается из публичной `drawBoardScene` и компонентных Android-тестов. Renderer приложения остаётся прежним.

## Реализованное рисование подписей координат

В `render/BoardCoordinatesRenderer.kt` находится обычная внутренняя функция `drawCoordinates(drawScope, orientation, squareSizePx, coordinateColor)`.

| Ориентация | Номера сверху вниз | Буквы слева направо |
|---|---|---|
| `WHITE` | 8…1 | a…h |
| `BLACK` | 1…8 | h…a |

- Номера рисуются слева внутри клеток с выравниванием текста влево, буквы — снизу внутри клеток с выравниванием по центру.
- Для размера клетки `s` координаты номера: `x = 0.1 * s`, базовая линия `y = row * s + 0.3 * s`.
- Координаты буквы: `x = column * s + 0.8 * s`, базовая линия `y = 8 * s - 0.2 * s`.
- Размер текста — `0.25 * s`, сглаживание включено. Положение и порядок арифметических операций сохраняют прежнюю отрисовку приложения.
- Цвет и его прозрачность берутся целиком из `coordinateColor`. Дополнительное `Paint.alpha = 100` не применяется; при подключении приложения прежнюю прозрачность нужно передать через `BoardRenderStyle.coordinateColor`.
- Размер клетки проверяется до рисования; неположительный или неконечный размер приводит к `IllegalArgumentException`.

Функция вызывается из публичной `drawBoardScene` между клетками и оформлениями, а также из компонентных Android-тестов. Подключение к приложению пока не выполняется.

## Публичная функция полной отрисовки сцены

В `render/BoardSceneRenderer.kt` находится обычная публичная функция `drawBoardScene(drawScope, scene, squareSizePx, style)`.

Она фиксирует единый порядок слоёв:

1. Клетки — `drawBoardSquares`.
2. Подписи — `drawCoordinates`.
3. Оформления в порядке списка — `drawSquareDecorations`.
4. Фигуры — `drawScenePieces`: неподвижные, анимируемые, затем перетаскиваемая.

Оформления могут закрывать подписи; фигуры рисуются поверх оформлений. Это соответствует существующему renderer приложения. Отдельные функции остаются внутренними деталями библиотеки; вызывающий код может использовать одну публичную точку входа.

Функция получает явный `DrawScope` и не создаёт `Canvas`, не управляет размерами layout, обрезкой, жестами или временем анимаций. Размер доски — восемь размеров клетки по каждой стороне от текущего начала координат. Пустая расстановка всё равно рисует клетки, подписи и оформления. Проверка размера выполняется первой компонентной функцией до рисования; исключения компонентных проверок проходят без обёрток.

Оба визуальных теста вызывают только `drawBoardScene`. Renderer приложения и его сцены пока остаются прежними.

## Согласованный контракт перемещения

### Ответственность сторон

1. Библиотека определяет исходную и конечную клетки действия пользователя.
2. Сообщает приложению о попытке перемещения.
3. Приложение решает, разрешено ли перемещение в текущем сценарии, и выполняет изменение.
4. Приложение сообщает результат библиотеке.

В игровой доске приложение может проверять и применять ход через `Position`. В тренировке дополнительно учитывается ожидаемый ход. В редакторе приложение может свободно изменять расстановку.

### Результат попытки

- При принятии приложение передаёт полную новую расстановку фигур.
- При отклонении библиотека сохраняет прежнюю расстановку и возвращает перетаскиваемую фигуру на исходную клетку.
- Полная новая расстановка учитывает перемещение ладьи при рокировке, удаление взятой фигуры, взятие на проходе и замену пешки при превращении.
- Конечное расположение фигур определяется приложением. Библиотека использует предыдущий и новый снимки для отображения перехода.

Форма API результата, способ доставки ответа и связывание ответа с конкретной попыткой ещё не определены.

### Превращение пешки

- Библиотека сообщает исходную и конечную клетки, например `e7 → e8`.
- Приложение определяет необходимость превращения, показывает диалог и выбирает фигуру вместе с пользователем.
- После выбора приложение выполняет ход и передаёт новую расстановку.
- При отмене выбора попытка завершается отклонением, фигура возвращается на исходную клетку.
- Редактор может разрешить простое перемещение пешки на последнюю горизонталь; библиотека не навязывает превращение.

### Блокировка ввода

- Одновременно обрабатывается одна попытка перемещения.
- До получения результата новые попытки перемещения заблокированы, включая время выбора фигуры для превращения.
- Перемещения также заблокированы до завершения всей очереди анимаций.
- В тренировке ввод включается после отображения и хода пользователя, и поставленного в очередь ответа противника.

### Отпускание фигуры за доской

Пока пользователь держит фигуру, её центр может выходить за границы доски. При отпускании за доской библиотека отменяет перетаскивание, возвращает фигуру на исходную клетку и сохраняет расстановку; запрос перемещения приложению не отправляется.

Если пользователь вернул указатель на доску и отпустил над клеткой, отправляется обычная попытка перемещения. Это поведение согласовано для будущего этапа взаимодействия, но ещё не реализовано.

### Замена позиции извне

При загрузке другой позиции приложение инициирует замену отображаемого состояния. Библиотека:

- отменяет незавершённую попытку;
- сбрасывает выделение и перетаскивание;
- сбрасывает текущие анимации и очередь;
- показывает новую расстановку;
- игнорирует запоздавший результат прежней попытки.

Обычное успешное завершение попытки с новой расстановкой и внешняя замена позиции должны различаться в будущем API. Механизм отмены и проверки актуальности ответа ещё предстоит определить.

## Согласованный контракт оформления клеток

Внешние оформления передаются универсальным упорядоченным списком. Для каждого оформления задаются:

- клетка;
- цвет заливки;
- при необходимости — цвет и толщина рамки.

Если несколько оформлений относятся к одной клетке, они рисуются в порядке списка.

Понятия `wrongMoveSquare` и `hintSquare` остаются в сценариях приложения. Приложение преобразует их в визуальные указания, например красную заливку для ошибки и зелёную заливку с рамкой для подсказки.

Типы оформления и функция их рисования реализованы. Сначала рисуется заливка, затем необязательная рамка. `Color.Transparent` позволяет задать только рамку, `border = null` — только заливку.

Толщина рамки задаётся долей размера клетки: `0.07f` означает 7%. `BoardSquareBorder` принимает только положительную конечную толщину; ноль, отрицательные значения, `NaN` и бесконечность приводят к `IllegalArgumentException`. Верхняя граница толщины не вводится.

При подключении существующих экранов преобразования выбора, последнего хода, ошибки и подсказки должны сохранять наблюдаемый порядок рисования. Общий библиотечный renderer реализован; адаптеры приложения пока не созданы.
